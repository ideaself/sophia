# 增量镜像同步设计

日期：2026-07-28
状态：已获用户批准（镜像模式 + 只删同步过的文件）

## 问题

当前 Push/Pull 是全量复制：每次传输所有文件（169MB PDF 也重传），且只增不删——本地删除的文件永远留在远端，无法管理远端数据。

## 设计决策（用户确认）

1. **镜像模式**：Push 使远端与本地一致；Pull 使本地与远端一致。与现有两个按钮的语义对应。
2. **只删同步过的文件**：依赖本地状态记录判断"曾经同步过"。从未同步过的文件（如本地新建未推送的角色）在任何方向都不会被删除。
3. **变更检测**：大小 + 修改时间。本地 mtime 只和历史本地 mtime 比，远端 lastmod 只和历史远端 lastmod 比，不存在跨时钟比较。

## 状态文件

`sync-state.json`，存于数据目录根，**不参与同步**（file-walker 排除），按设备独立。

```json
{
  "version": 1,
  "files": {
    "profiles/.../story.md": {
      "localSize": 123, "localMtimeMs": 1720000000000,
      "remoteSize": 123, "remoteLastmod": "Tue, 01 Jan 2030 00:00:00 GMT"
    }
  }
}
```

## Push 流程

1. 读取状态；若无状态，用远端清单播种（条目只含 remote 字段，local 为 null）——使首次 Push 即可清理远端存量垃圾。
2. 列出本地可同步文件与远端清单（含 size/lastmod）。
3. 上传：本地文件满足以下任一条件 → 传输；否则跳过：
   - 不在状态中；
   - 状态 local 字段与当前本地 stat 不符（本地改了）；
   - 状态 remote 字段与当前远端清单不符（远端被别的设备改过）。
4. 删除：远端文件在状态中但本地不存在 → 删除。不在状态中的远端文件不动。
5. 逐文件成功后更新状态；结尾落盘。Push 完成后重新列一次远端刷新 remote 字段（避免下次 Pull 误判）。

## Pull 流程

1. 读取状态；无状态 → 空状态（首次 Pull 只下载、绝不删本地）。
2. 列出远端清单。
3. 下载：远端文件满足以下任一条件 → 传输；否则跳过：
   - 不在状态中；
   - 状态 remote 字段与当前远端清单不符；
   - 状态 local 字段与当前本地 stat 不符（本地被改过 → 远端覆盖，与现行"拉取覆盖本地"语义一致）。
4. 删除：状态中的条目远端已不存在且本地文件存在 → 删除本地文件。不在状态中的本地文件绝不动。
5. 下载后从 fs.stat 记录 local 字段，从远端清单记录 remote 字段；结尾落盘。

## UI

- Push/Pull 点击后先调 `sync:plan-{push,pull}` 获取 `{transferCount, skipCount, deleteCount, deleteSample[]}`；deleteCount > 0 时弹确认框（列出样本，最多 20 条）再执行。
- 结果消息：`Pushed 5, skipped 12, deleted 3`。
- 进度条只对实际传输/删除的文件推进。

## 错误处理

- 单文件失败计入 errors，不影响其他文件；失败条目不更新状态（下次重试）。
- 删除失败同样计入 errors。

## 测试

- sync-state：缺失→null、保存/读取往返。
- sync-manager（FakeClient 注入）：跳过未变更、上传新增/变更、删除同步过的远端多余文件、首次播种清理、Pull 对称用例、从不删未同步文件。

## 修订（2026-07-28，参考 anx-reader）

问题：另一台机器 Pull 会多出文件——旧版全量上传把 `config/*.enc`、`sync-state.json` 留在了服务器上，而 Pull 无任何过滤，全部镜像到本地；这些垃圾又永远进不了推送端的状态记录，镜像删除永远清不掉。

决策（对齐 anx-reader "同步集合由应用定义" 的模型）：

1. **同步集合单一定义**：`file-walker.isSyncableRelPath()` 推拉共用。Pull 跳过不符合规则的远端文件（不下载）；这些文件也不计入 remoteRelSet，因此本地已被污染的副本会被镜像删除自动清除。
2. **Push 垃圾回收**：不符合同步规则的远端文件判定为垃圾，无需状态记录直接删除——服务器上的历史垃圾清一次就永远干净。播种时也不再记录垃圾。
3. **提速**：传输与远程目录遍历改为 4 路并发（`async-pool.runPool`）；远程目录由"每文件 exists+mkdir"改为按去重后的父目录集合预创建一次。并发度保持低位，避免触发坚果云等 WebDAV 服务商的限流。
4. **空目录清理**：镜像删除文件后，两侧被清空的目录一并移除（本地向上修剪至 dataRoot；远端按删除路径的祖先目录从最深处先试列后删——WebDAV 对非空集合的 DELETE 可能递归删除内容，所以删前必须用新列表确认空）。`/sophia` 前缀本身永不在候选内；清理失败静默忽略。
